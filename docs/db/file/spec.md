## 1. 范围

- 上传、去重、解析、分片、向量化、删除（软删）与引用检查。
- 不做：批量多选上传（支持单文件与文件夹拖拽，逐个入库）、版本链、按知识库重切、文件更新/覆盖、审计表、租户配额、下载/预览原文、病毒扫描与 OCR。
- 知识库只引用**文件**；`kb_file` 桥接表**等知识库原型确定后再建**，本轮 DDL 不含它。

## 2. 已定决策

| D-08 | 摄取任务：单机线程池 2–4 并发，失败最多重试 3 次 |

## 3. 状态机

```
pending ──chunk──▶ chunking ──ok──▶ chunked ──embed──▶ embedding ──ok──▶ ready
   ▲                    │                                │
   │                    └──── fail ──▶ failed ◀──────────┘
   └────────── 重新分片（人工）──────────┘
```

- `chunking` / `embedding` 为任务执行中；同一文件同一时刻只允许一个活动任务。
- `failed` 可由人工「重试」回到 `chunking`（新任务，attempt 重置）。

## 4. 实体与关系

| 表 | 说明 |
|---|---|
| `file` | 文件元数据、内容 hash、存储 key、状态、embedding 模型/维度 |
| `file_chunk` | 分片文本与向量（`vector(1024)`），属于文件 |
| `ingest_task` | 分片/向量化任务，状态、重试次数、错误 |

关系：`file 1—* file_chunk`；`file 1—* ingest_task`。
知识库引用（`kb_file`）等知识库原型确定后再建，届时补 `file *—* knowledge_base`。

派生字段（不落库）：`chunk_count`、`reference_count` 由聚合查询得出。

## 6. 访问路径（TOP）

1. 列表：`tenant_id + deleted_at IS NULL` 按 `created_at DESC` 分页，聚合 chunk/reference 计数。
2. 详情：按 `file_id` 取文件与分片（`deleted_at IS NULL`，按 `chunk_index` 分页）。
3. 检索（知识库模块接入后）：`kb_file(kb_id) → file_chunk` 过滤，`embedding <=> query` 排序取 top-k（cosine）。
4. 任务轮询：`status IN ('pending')` 按 `created_at` 取任务。

## 7. 待确认 / 风险

- `kb_file` 与 `knowledge_base` 均推迟到知识库模块；届时补 `kb_id` 物理外键，并启用 R-004 的删除拦截。
- 体验期没有角色模型，同租户成员可执行全部操作（D-16）；认证落地后需补「上传者或管理员」校验。
- 审计表、租户配额为显式后续项（D-19），上线前必须补齐或书面接受风险。
- MIME 嗅探依赖 Tika detect，与 RAG reader 的 Tika 依赖同源，引入时统一版本。
- `uploader_id` 指向体验期内存用户，暂无外键；正式认证落地后再评估。
- HNSW 索引参数（`m`、`ef_construction`）需按量级压测后调整；本期先建默认参数索引。
- 20MB 上限与 500 字分片参数需要按真实文档回归一次。
- 分片/向量化的失败重试是否需要退避策略，待实现阶段定。
